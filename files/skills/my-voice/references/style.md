## 1. 문장 구조 습관

코퍼스에서 반복적으로 관찰된 것들. 존댓말로 바꿔도 **이 구조는 유지한다.**

### 결론 먼저
판단이나 답을 첫 문장에 놓고, 근거를 뒤에 붙인다. 배경 설명으로 시작하지 않는다.

### 한 문장에 한 가지
접속사로 잇지 않고 줄을 바꾼다. 평균 문장 길이가 짧다 (전체 메시지 중앙값 51자).

```
결론부터 말하면 지금 구조로는 불가능합니다.
스키마 변경이 같이 들어가야 합니다.
```

### 조사 생략
"이 부분에 대한 확인이 필요합니다" 보다 "이 부분 확인 필요합니다".
관형격 조사(의), 목적격 조사(을/를)를 자주 생략한다.

### 단서는 괄호로 뒤에
문장을 복잡하게 만들지 않고 괄호로 덧붙인다. 코퍼스에 반복적으로 나타나는 가장 특징적인 습관이다.

```
2.3.0-alpha6으로 정리하겠습니다. (이미 해결됨/종료 상태는 제외)
로컬에서 실제 데이터로 검증했습니다. (테스트 코드가 아니라 API 직접 호출)
```

### 번호로 나눈다
확인할 게 2개 이상이면 1. 2. 3. 으로 나눈다. 불릿(-)보다 번호를 쓴다.

### 되묻기
확신이 없으면 상대에게 판단을 넘긴다. "~가 맞을까요?", "~인지 확인 부탁드립니다."

## 2. 어미 변환표

지시 말투(반말) → 티켓 댓글(존댓말). 왼쪽은 코퍼스 상위 빈도 어미다.

| 반말 (코퍼스) | 빈도 | 존댓말 변환 |
|---|---|---|
| ~해줘 / ~해주고 | 272 | ~부탁드립니다 / ~해주시면 됩니다 |
| ~알려줘 | 52 | ~공유드립니다 / ~알려주시면 감사하겠습니다 |
| ~남겨줘 | 28 | ~남기겠습니다 |
| ~해야해 | 29 | ~해야 합니다 / ~이 필요합니다 |
| ~할거야 / ~할게 | 50 | ~하겠습니다 |
| ~인거야? / ~맞아? | 28 | ~인가요? / ~맞을까요? |
| ~있는지 / ~된건지 | 87 | ~있는지 확인했습니다 / ~인지 확인 부탁드립니다 |
| ~같아 / ~같은데 | — | ~할 것 같습니다 / ~로 보입니다 |
| ~하자 | 25 | ~하겠습니다 / ~하면 될 것 같습니다 |
| ~안해도 돼 | — | ~는 하지 않아도 됩니다 |
| ~아니야? | — | ~아닐까요? / ~여야 하지 않을까요? |

### 톤 강도

원문이 강해도 티켓 댓글에서는 중립으로 낮춘다.

```
반말: 쓸데없이 테이블 만든거 같은데
댓글: 기존 filter API에 이미 있는 값이라 별도 테이블은 불필요해 보입니다.
```

```
반말: 내용 똑바로 안봐?
댓글: 아래 문구 기준으로 다시 확인 부탁드립니다.
```

## 3. 어휘

### 쓰는 말
정리, 확인, 공유, 반영, 적용, 진행, 처리, 검토, 대응, 남기다, 채우다, 빼다, 넘기다,
작업 티켓, 하위 작업 티켓, 스토리 티켓, 수정 버전, 영향을 받는 버전, 변동사항, 미공지

### 쓰지 않는 말
취합, 상신, 기재, 사료됩니다, 부득이하게, 검토 후 회신드리겠습니다(정형 문구),
살펴보도록 하겠습니다, 말씀 주신 바와 같이

### 인사말
쓰지 않는다. "안녕하세요", "수고하십니다", "감사합니다" 로 시작하거나 끝맺지 않는다.
필요하면 마지막 줄에 "확인 부탁드립니다." 한 줄만.

느낌표는 짧은 회신에서만 한 번. "확인후 답변드리겠습니다!" 정도.

## 6. 코퍼스의 한계

스타일을 갱신할 때 알고 있어야 하는 것들.

- 코퍼스는 **Claude에게 보낸 지시문**이 대부분이다. 동료용 존댓말 원본은 소수다.
  기준 샘플(예시 3번)과 실제 게시된 답변 몇 건이 존댓말 근거의 전부다.
- 사용자가 **붙여넣은 남의 글**(동료 슬랙 메시지, 지라 댓글, 채용 공고)이 섞여 있다.
  추출기는 이걸 구분하지 못한다. 존댓말 문장이 나온다고 전부 본인 문체로 보면 안 된다.
- 프로젝트별로 레지스터가 다르다. `vc-monorepo`는 업무 지시, `Downloads`는 여행·잡담,
  `Downloads-resume`은 영문 지원서 작업이다. 티켓 댓글 스타일은 `vc-monorepo` 계열이 기준이다.
